1. Prerequisites & AWS Account

▶
AWS account with billing alerts
Set billing alarm at $50, $100, $200 in CloudWatch → Billing. Enable Cost Anomaly Detection. Tag everything: env=production, app=sayvors.
IAM user for deployment (not root)
Create IAM user with programmatic access. Attach: AmazonEC2FullAccess, AmazonRDSFullAccess, AmazonElastiCacheFullAccess, AmazonS3FullAccess, SecretsManagerReadWrite, IAMReadOnlyAccess, CloudWatchFullAccess, AmazonSSMFullAccess. Store credentials in password manager — never in code.
Install AWS CLI v2 locally
aws configure with IAM credentials. Default region: me-central-1. Verify: aws sts get-caller-identity.
Docker + Docker Compose installed locally
Needed for building and testing the image before pushing to GHCR.
GitHub Actions secrets set
Ensure GITHUB_TOKEN has packages:write. Add AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY as repo secrets if using AWS CLI in CI.
Domain DNS ready
sayvors.com registered. Decide: Route 53 or keep Cloudflare. Cookie domain is .sayvors.com.

2. VPC & Networking

▶
Create VPC
VPC CIDR 10.0.0.0/16. Name: sayvors-prod-vpc. Region: me-central-1.
Create Subnets (2 AZs)
  • Public A: 10.0.1.0/24 in me-central-1a
  • Public B: 10.0.2.0/24 in me-central-1b
  • Private A: 10.0.10.0/24 in me-central-1a
  • Private B: 10.0.11.0/24 in me-central-1b
Enable auto-assign public IP on public subnets.
Internet Gateway + Route Table
Create IGW, attach to VPC. Public route table: 0.0.0.0/0 → IGW. Associate with both public subnets. Private subnets: no IGW route (or add NAT Gateway — skip for cheapest, put EC2 in public subnet).
Create Security Groups
  • sg-ec2: Inbound 80, 443 from 0.0.0.0/0. Outbound: all. Tag: sayvors-ec2-sg
  • sg-rds: Inbound 5432 from sg-ec2 only. Tag: sayvors-rds-sg
  • sg-redis: Inbound 6379 from sg-ec2 only. Tag: sayvors-redis-sg
VPC Endpoints (optional, saves NAT cost)
Gateway endpoint for S3 (free). Interface endpoints for Secrets Manager, CloudWatch Logs. Avoids NAT Gateway charges for AWS service traffic.
For the 1-box cheapest setup, put EC2 in a public subnet with an Elastic IP. No NAT Gateway needed.

3. EC2 Instance

▶
Create IAM Role for EC2
IAM Role: sayvors-ec2-role. Attach: AmazonS3FullAccess, SecretsManagerReadWrite, CloudWatchAgentServerPolicy, AmazonSSMManagedInstanceCore. Instance profile — no access keys needed.
Launch EC2 Instance
  • AMI: Amazon Linux 2023 (or Ubuntu 24.04 LTS)
  • Instance type: m6i.large (2 vCPU, 8 GB) — non-burstable. Or t3.large (cheaper, burstable).
  • Subnet: public subnet A · Security group: sg-ec2
  • IAM instance profile: sayvors-ec2-role
  • Storage: 100 GB gp3, encrypted (default KMS key)
  • Key pair: create or use existing · Termination protection: Yes · Detailed monitoring: Yes
  • User data: install Docker + Docker Compose (see below)
User Data — Install Docker & Compose
#!/bin/bash
set -euxo pipefail
dnf update -y
dnf install -y docker git
systemctl enable --now docker
usermod -aG docker ec2-user
mkdir -p /usr/local/lib/docker/cli-plugins
curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-$(uname -m) \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
mkdir -p /opt/sayvors
chown ec2-user:ec2-user /opt/sayvors
dnf install -y amazon-cloudwatch-agent
Allocate Elastic IP
Allocate EIP and associate with the instance. Stable public IP for DNS. Tag: sayvors-prod-eip.
EBS Snapshot Schedule
AWS Backup or DLM: daily snapshots, 7-day retention. Tag: sayvors-prod-snapshots.
SSH in and verify Docker
ssh ec2-user@<EIP> → docker --version && docker compose version. Verify instance profile: aws sts get-caller-identity.

4. RDS PostgreSQL (Production Database)

▶
Create DB Subnet Group
RDS → Subnet groups → Create. Name: sayvors-prod-db-subnet. VPC: sayvors-prod-vpc. Subnets: private A + B.
Create RDS Instance
  • Engine: PostgreSQL 16 (≥16.5 for pgvector 0.8.2)
  • Template: Production (or Dev/Test for cheaper)
  • DB instance ID: sayvors-prod-db
  • Master username: sayvors_admin (not "postgres")
  • Master password: generate strong (32+ chars), store in SSM
  • Instance class: db.t4g.medium (2 vCPU, 4 GB) — cheapest viable. Or db.m6g.large (2 vCPU, 8 GB) for headroom.
  • Storage: gp3, 100 GB, autoscaling enabled (max 200 GB), encrypted (default KMS)
  • Multi-AZ: No (single-AZ for cheapest; enable later for HA)
  • VPC: sayvors-prod-vpc, subnet group: sayvors-prod-db-subnet
  • Security group: sg-rds · Public access: No
  • Database name: sayvors
  • Backup retention: 7 days (PITR) · Backup window: 02:00–03:00 UTC
  • Maintenance window: Sun 04:00–05:00 UTC
  • Enhanced monitoring: Yes (60s) · Performance Insights: Yes (7 days free)
  • Deletion protection: Yes · Auto minor version upgrade: Yes
Create Application DB User (least privilege)
Connect as master. Run: 
CREATE USER sayvors_app WITH PASSWORD 'STRONG_PASSWORD_HERE';
GRANT CONNECT ON DATABASE sayvors TO sayvors_app;
GRANT USAGE ON SCHEMA public TO sayvors_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO sayvors_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO sayvors_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO sayvors_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO sayvors_app;
Enable pgvector Extension
Connect as master or app user: CREATE EXTENSION IF NOT EXISTS vector; Verify: SELECT * FROM pg_available_extensions WHERE name = 'vector';
Run Alembic Migrations
From EC2 box: docker compose -f docker-compose.prod.yml run --rm api alembic upgrade head. Verify single head: alembic heads → exactly 1.
Verify Connection from EC2
psql "postgresql://sayvors_app:PASSWORD@RDS_ENDPOINT:5432/sayvors?ssl=require" -c "SELECT 1;". Or check /readyz after deploy.
Rehearse One Restore (OPS-1)
Create manual snapshot → restore into temp DB → run app against it → verify data → delete temp → write runbook. Most important step. Un-rehearsed backups are not backups.
RDS credentials go in SSM — never in .env files on the box or in git.

5. ElastiCache Redis (Auth Infrastructure)

▶
Create Cache Subnet Group
ElastiCache → Subnet groups → Create. Name: sayvors-prod-redis-subnet. VPC: sayvors-prod-vpc. Subnets: private A + B.
Create Redis Replication Group
  • Engine: Redis 7.x · Cluster mode: Disabled
  • Name: sayvors-prod-redis
  • Node type: cache.t4g.small (1.5 GB) — cheapest viable. Or cache.t4g.medium (3 GB) for headroom.
  • Replicas: 1 (for failover; 0 for cheapest) · Multi-AZ: Yes (if replicas > 0)
  • VPC: sayvors-prod-vpc, subnet group: sayvors-prod-redis-subnet
  • Security group: sg-redis
  • Encryption at rest: Yes · Encryption in transit: Yes (TLS)
  • Auth token: Yes — generate strong password, store in SSM
  • Parameter group: custom with maxmemory-policy noeviction
Set maxmemory-policy to noeviction
ElastiCache → Parameter groups → Create custom from default. Set maxmemory-policy = noeviction. Apply to replication group. Reboot if required.
Verify Connection from EC2
redis-cli -h REDIS_ENDPOINT -p 6379 --tls -a AUTH_TOKEN ping → PONG. Or set REDIS_URL=rediss://:AUTH_TOKEN@REDIS_ENDPOINT:6379/0 and check /readyz.
Redis holds auth state (OTPs, rate limits, JWT blacklist, sessions). Fails closed — a Redis outage locks everyone out. ElastiCache multi-AZ = automatic failover.

6. S3 (Object Storage)

▶
Create S3 Buckets
  • Media (public): sayvors-media-prod — owner photos/videos. Block Public Access: OFF. SSE-S3 encryption. Bucket policy: s3:GetObject for * on media/*.
  • Docs (private): sayvors-docs-prod — databank uploads, scrapes. Block Public Access: ON. SSE-S3 or SSE-KMS. Never reuse media bucket.
  • Backups: sayvors-backups-prod — pg_dump dumps. Block Public Access: ON. SSE-S3. Lifecycle: Glacier after 30 days, expire after 90 days.
Enable Versioning on All Buckets
S3 → each bucket → Properties → Versioning → Enable.
Set CORS on Media Bucket
Allow GET from https://*.sayvors.com. Needed for browser-based media fetches.
Migrate Existing Local Uploads
aws s3 sync ./data/uploads/media s3://sayvors-media-prod/media/ and aws s3 sync ./data/uploads s3://sayvors-docs-prod/docs/. Verify: aws s3 ls s3://sayvors-media-prod/media/ --recursive.
Set Environment Variables
S3_MEDIA_BUCKET=sayvors-media-prod
S3_DOCS_BUCKET=sayvors-docs-prod
AWS_REGION=me-central-1
S3_MEDIA_PUBLIC_BASE_URL=https://sayvors-media-prod.s3.me-central-1.amazonaws.com
Never point S3_DOCS_BUCKET at the public media bucket. Private docs must stay private.

7. Secrets Management (SSM Parameter Store)

▶
Create SSM Parameters (SecureString)
SSM → Parameter Store → Create parameter (SecureString, default KMS key): /sayvors/prod/DATABASE_URL, /sayvors/prod/REDIS_URL, /sayvors/prod/KAFKA_BOOTSTRAP_SERVERS, /sayvors/prod/JWT_SECRET, /sayvors/prod/CHANNEL_ENCRYPTION_KEY, /sayvors/prod/ADMIN_PASSWORD_HASH, /sayvors/prod/RESEND_API_KEY, /sayvors/prod/GOOGLE_CLIENT_SECRET, /sayvors/prod/META_APP_SECRET, /sayvors/prod/EMAIL_UNSUBSCRIBE_SECRET, /sayvors/prod/GLITCHTIP_DSN. Non-secret config (ALLOWED_HOSTS, CORS_ORIGINS, etc.) can go in a plain .env.prod file on the box.
Create .env.prod on the EC2 box
SSH into EC2. Create /opt/sayvors/.env.prod from deploy/env.prod.example. Fill in all values. For secrets, pull from SSM: aws ssm get-parameter --name /sayvors/prod/DATABASE_URL --with-decryption --query Parameter.Value --output text.
Verify Production Validator Passes
On the EC2 box: cd /opt/sayvors && docker compose -f docker-compose.prod.yml config. Then start the API: docker compose -f docker-compose.prod.yml up -d api. Check logs: docker compose -f docker-compose.prod.yml logs api. The validate_production_settings() must pass (no FATAL errors). If it fails, fix the config before proceeding.
Never commit .env.prod to git. The root .gitignore already excludes .env*.

8. Load Balancer (ALB) — For 2-Box HA (Skip for 1-Box)

▶
For the 1-box cheapest setup, skip this section. Caddy terminates TLS on the box directly. Come back here when you add the second box.
Request ACM Certificate
ACM → Request certificate → Public. Domain: api.sayvors.com. Validation: DNS. Wait for status: Issued.
Create Target Group
  • Type: Instances · Protocol: HTTP, Port: 80
  • VPC: sayvors-prod-vpc
  • Health check: HTTP, path /readyz, interval 30s, timeout 10s, healthy threshold 2, unhealthy 3
  • Health check success codes: 200 · Host header: api.sayvors.com
  • Deregistration delay: 30s (matches graceful shutdown)
Create ALB
  • Name: sayvors-prod-alb · Scheme: Internet-facing
  • VPC: sayvors-prod-vpc, subnets: public A + B
  • Security group: allow 443 from 0.0.0.0/0, 80 from 0.0.0.0/0
  • Listeners: HTTPS 443 → target group (ACM cert), HTTP 80 → redirect to HTTPS
Register EC2 Instances in Target Group
Add both EC2 instances. Wait for health status: Healthy. If unhealthy, check security groups, health check path, Host header, and that the app is running.
ALB Path Rules (Block Sensitive Paths)
Add listener rules: if path is /metrics or /docs* or /openapi.json or /redoc*, return 403. Or rely on Caddy if still in the chain.
Route 53 — Point Domain at ALB
Route 53 → Hosted zone → Create record: api.sayvors.com → A (Alias) → ALB.
Update TRUSTED_PROXIES
Set TRUSTED_PROXIES=["10.0.0.0/16"] in .env.prod on both boxes. This makes the app trust X-Forwarded-For from the ALB.

9. Caddy Configuration

▶
Option A: Caddy terminates TLS (1-box, no ALB)
Use the existing deploy/Caddyfile as-is. Caddy auto-provisions a Let's Encrypt cert for api.sayvors.com. Ports 80 + 443 open on the security group. No changes needed.
Option B: Caddy behind ALB (HTTP only)
ALB terminates TLS (ACM). Caddy listens on port 80 internally. Update Caddyfile: 
:80 {
  @blocked path /metrics /docs /docs/* /redoc /redoc/* /openapi.json
  respond @blocked 403
  header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload"
  reverse_proxy api:8000
}
Remove the TLS block and domain block. Caddy no longer needs port 443.
Option C: Remove Caddy entirely
ALB → API directly. Add path blocks as ALB listener rules. Simpler, one less hop. The app already disables /docs in production. Just block /metrics at the ALB.
For the 1-box cheapest setup, use Option A (Caddy auto-TLS). For 2-box HA, use Option B or C.

10. Application Deployment

▶
Clone repo on EC2
cd /opt/sayvors && git clone https://github.com/Sayvors/sayvors.git . Checkout the production or staging branch.
Create .env.prod
Copy deploy/env.prod.example to .env.prod. Fill in all values. Key settings: ENVIRONMENT=production, DATABASE_URL=postgresql+asyncpg://sayvors_app:PASSWORD@RDS_ENDPOINT:5432/sayvors?ssl=require, REDIS_URL=rediss://:AUTH_TOKEN@REDIS_ENDPOINT:6379/0, KAFKA_BOOTSTRAP_SERVERS=MSK_BROKER_1:9092,MSK_BROKER_2:9092,MSK_BROKER_3:9092, S3_MEDIA_BUCKET=sayvors-media-prod, S3_DOCS_BUCKET=sayvors-docs-prod, ALLOWED_HOSTS=["api.sayvors.com"], CORS_ORIGINS=["https://app.sayvors.com"], COOKIE_DOMAIN=.sayvors.com, COOKIE_SECURE=true, COOKIE_SAMESITE=none, RUN_BACKGROUND_WORKERS=false, TESTING=false, GOOGLE_REVIEWS_MOCK=false.
Pull the Docker Image
docker pull ghcr.io/sayvors/sayvors-api:staging (or SHA-pinned tag). Verify: docker images | grep sayvors-api.
Run Migrations (One-Shot)
docker compose -f docker-compose.prod.yml run --rm api alembic upgrade head. Verify: docker compose -f docker-compose.prod.yml run --rm api alembic heads → exactly 1 head.
Start Services
docker compose -f docker-compose.prod.yml up -d. Check: docker compose -f docker-compose.prod.yml ps. All services should be healthy.
Verify Health Endpoints
  • curl https://api.sayvors.com/health → 200, no deps checked
  • curl https://api.sayvors.com/readyz → 200, all deps healthy
  • curl https://api.sayvors.com/metrics → 403 (blocked by Caddy/ALB)
Verify Login Flow
Open the web app. Log in. Check DevTools → Cookies: access_token and refresh_token are httpOnly, Secure, SameSite. Check Network tab: no access_token in JSON response body.
Test Upload (S3)
Upload a media file and a databank doc. Verify they land in S3: aws s3 ls s3://sayvors-media-prod/media/ --recursive. Verify the public URL is fetchable. Verify the private doc is not public.
Test WhatsApp Webhook
Send a test message to the WhatsApp number. Verify it appears in the inbox. Check worker logs: docker compose -f docker-compose.prod.yml logs worker. AI reply should be generated and sent.
SHA-Pin the Image
Update docker-compose.prod.yml: change image: ghcr.io/sayvors/sayvors-api:staging to image: ghcr.io/sayvors/sayvors-api:SHA (the commit SHA). Commit and push. This ensures rollback to a known-good image.

11. Backups & Disaster Recovery

▶
Verify RDS PITR
RDS → sayvors-prod-db → Maintenance & backups → Automated backups: Enabled, retention 7 days. Verify: aws rds describe-db-instances --db-instance-identifier sayvors-prod-db --query 'DBInstances[0].BackupRetentionPeriod' → 7.
Schedule Nightly pg_dump → S3
On the EC2 box, add a cron job: 
0 2 * * * cd /opt/sayvors && DATABASE_URL="postgresql://sayvors_app:PASSWORD@RDS_ENDPOINT:5432/sayvors" S3_DOCS_BUCKET=sayvors-backups-prod AWS_REGION=me-central-1 python scripts/db_backup.py >> /var/log/db_backup.log 2>&1
Or use EventBridge + SSM Run Command / Lambda for a serverless schedule.
Rehearse One Restore
  1. Create a manual RDS snapshot.
  2. Restore it into a new temporary DB instance.
  3. Point a test DATABASE_URL at the temp instance.
  4. Run the app against it (or just run alembic current + a few queries).
  5. Verify data integrity (row counts, recent records).
  6. Delete the temp instance.
  7. Write the runbook in docs/operations/.
This is the single most important step. Un-rehearsed backups are not backups.
S3 Backup Lifecycle
On sayvors-backups-prod: S3 → Management → Lifecycle rules. Transition to Glacier after 30 days. Expire after 90 days. This keeps backup costs low.

12. Monitoring & Alerting

▶
CloudWatch Agent on EC2
Install the CloudWatch agent on the EC2 box. Configure it to ship: CPU, memory, disk, and the Docker container logs. Use the SSM parameter for config. Or skip and rely on local logs + GlitchTip.
CloudWatch Alarms
Create alarms (SNS topic → email) for: EC2: CPU > 80% for 5 min, memory > 85%, disk > 80%. RDS: CPU > 80%, free storage < 10 GB, connections > 80% of max, read/write latency > 50ms. ElastiCache: memory utilization > 75%, evictions > 0, CPU > 80%. ALB (if used): 5xx > 1%, target unhealthy count > 0, latency p99 > 2s.
External Uptime Monitor
UptimeRobot / Better Stack (free tier): monitor https://api.sayvors.com/readyz every 5 min. Alert on 2 consecutive failures. This is the "the box is down and nobody knows" safety net.
GlitchTip DSN
Set GLITCHTIP_DSN in .env.prod. Verify errors appear in GlitchTip by triggering a test error (e.g., hit a non-existent endpoint). Both API and worker processes report.
Prometheus Scrape
Ensure deploy/prometheus.yml is mounted and Prometheus is running. Scrape target: api:8000/metrics. Verify: curl http://localhost:9090/targets shows the API target as UP.

13. Security Policies & Hardening

▶
IAM Least Privilege
The EC2 instance profile should have: S3 read/write on the 3 buckets only, SSM read on /sayvors/prod/*, CloudWatch Logs write, SSM session manager. No * resources. No access keys in env files.
RDS Encryption at Rest
RDS → sayvors-prod-db → Encryption: Enabled (default KMS key). Verify: aws rds describe-db-instances --db-instance-identifier sayvors-prod-db --query 'DBInstances[0].StorageEncrypted' → true.
S3 Encryption at Rest
All 3 buckets: Properties → Default encryption → SSE-S3 (or SSE-KMS). Block Public Access on docs + backups buckets: ON.
CloudTrail Enabled
CloudTrail → Create trail → All regions, management events + data events (S3). Send logs to the backups bucket or a dedicated CloudTrail bucket. This is your audit trail.
VPC Flow Logs
VPC → Flow logs → Create. Send to CloudWatch Logs. This helps debug network issues and security investigations.
Security Group Audit
Verify: sg-ec2 allows 80/443 from 0.0.0.0/0 only. sg-rds allows 5432 from sg-ec2 only. sg-redis allows 6379 from sg-ec2 only. No 0.0.0.0/0 on database ports. No SSH (22) open to the world — use SSM Session Manager instead.
SSM Session Manager (No SSH)
Instead of opening port 22, use SSM Session Manager to access the EC2 box. The instance profile already has AmazonSSMManagedInstanceCore. Connect: aws ssm start-session --target i-INSTANCE_ID. Remove SSH key pair from the security group.
Production Validator Passes
Verify validate_production_settings() passes on boot. Check logs for "FATAL" — there should be none. The app refuses to start with localhost in CORS/redirect URIs, wildcard hosts, missing admin hash, etc.
TESTING and GOOGLE_REVIEWS_MOCK are OFF
Verify in .env.prod: TESTING=false and GOOGLE_REVIEWS_MOCK=false. The production validator rejects true for both.

Monitor for 24 hours
